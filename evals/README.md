# 评测与基线（evals/）

Fast 档 0 次 LLM 调用，所以评测**零 API 成本、可无限重复**。评测器同时负责记录基线、比对漂移、
离线验证 Standard 档链路、以及估费。

**评测文件字段名**：历史集合用 `text`，新采集的集合可能写成 `input`——评测器两者都收，
**缺字段会直接报错退出**（不再把整集当 `undefined` 跑出一份 0 分的假报告）。

**标注口径**：完整判据、边界规则与"标签变更协议"见 [ANNOTATION.md](D:\project\deepseek\evals\ANNOTATION.md)。

- `write` 从零产出新文本 ｜ `transform` 对已有文本再加工（改写/压缩/润色/换语气/翻译/转格式）
- `code` 要代码、SQL，或对代码/SQL 再加工（此处 `code` 优先于 `transform`）｜ **`code` 也优先于 `plan`**：
  请求对象是已有代码/SQL/配置时，"有没有办法/怎么改/咋整"都归 `code`
- `analyze` 对**具体现象/现场**归因 ｜ `plan` 要**可执行步骤/做法/取值**
- `extract` 从给定材料里抠出信息 ｜ `decide` 在多个选项中做选择
- `review` 挑错、找漏洞、核对 ｜ `learn` 搞懂**通用概念/原理** ｜ `converse` 寒暄或无实质请求
- **边界样本写数组**（`["plan","analyze"]`，第一个元素是主标签）：严格口径只认主标签，
  宽松口径命中任一即算对，两个数**同时**报告——禁止只报宽松口径。

## 命令

```bash
node evals/run.js                                   # 盲测集（fast 档）
node evals/run.js --file dev.jsonl                  # 指定集合
node evals/run.js --file samples.jsonl --record     # 记录基线 → baseline.fast.json
node evals/run.js --file samples.jsonl --diff baseline.fast.json   # 与基线比对漂移（改了规则后跑）
node evals/run.js --file inputs.local.jsonl --record baseline.local.json
npm run eval:holdout                                # 留出集（fast 档）→ baseline.fast.holdout.json

# Standard 档（1 次 LLM 调用/条）
node evals/run.js --tier standard --estimate                       # 只估费，不发请求
node evals/run.js --tier standard --limit 6 --mock mock.demo.jsonl # 离线 mock 跑链路（0 真实请求）
node evals/run.js --tier standard --limit 3 --max-cost 0.02        # 真实端点，先小额试跑
node evals/run.js --tier standard --file inputs.local.jsonl --record baseline.standard.json
npm run eval:holdout:standard                       # 留出集真实跑 → baseline.standard.holdout.json

node evals/run.js --compare baseline.local.json baseline.standard.mock.json   # 两份快照对照
npm run eval:holdout:compare                        # Fast vs Standard 的留出集对照

# 重算：标签修订后 0 成本重出指标（用快照里已记录的预测，不重新调用模型）
node evals/run.js --recompute baseline.standard.json --file inputs.local.jsonl

# 第二留出集（holdout2.jsonl，v01–v20，公开社区提问帖）
npm run eval:holdout2                               # fast 档 → baseline.fast.holdout2.json
npm run eval:holdout2:standard                      # 真实跑一遍（≈¥0.02）→ baseline.standard.holdout2.json
npm run eval:holdout2:compare                       # Fast vs Standard 逐样本对照（0 次 LLM）
npm run eval:holdout2:recompute                      # 标签修订后 0 成本重出指标
```

其他参数：`--limit N`（只跑前 N 条）、`--max-cost <元>`（运行预算上限，默认 0.5）。
退出码：`0` 全绿｜`1` 有判错/违规/降级（**真实基线本来就该是 1**）｜`2` 用法或配置错误。
快照默认写 `baseline.<tier>.json`（mock 为 `baseline.standard.mock.json`），只存指标与散列，
**不存原文**；`inputs.local.jsonl` / `baseline.local.json` 已在 `.gitignore` 里（防 PII 入库）。

⚠️ **Windows PowerShell 的 `>` 重定向会写坏 JSON（实测）**：`node evals/run.js … > out.json` 生成的是
**UTF-16LE 带 BOM** 文件（实测前 3 字节 `ff fe 7b`），下游 `JSON.parse` 直接报
`SyntaxError: Unexpected token '\uFEFF'`——CLI 自身并不写 BOM。规避：读侧按 BOM 判断编码后再解码，
或改用 `| Set-Content -Encoding utf8` / `| Out-File -Encoding utf8`。
（同理：**受限 PowerShell 里内联传 JSON 要把内部引号写成 `\"`**，裸双引号会被吞；回答较多时用 CLI 的
`--answers-file <path>` 更稳。CLI 的 `--ask` + `--answers` / `--answers-file` 用法见根 [README.md](D:\project\deepseek\README.md)。）

样本行格式（`expect` 可省略＝未标注，只记基线、不算准确率；`task_type` 写数组＝可接受集合）：

```json
{"id":"b01","text":"帮我把这段话回得客气点","expect":{"task_type":"transform","deliverable_format":"table"}}
```

1. **口语化改写完全没有词表**：盲测集 6/30、真实 20 条里同样成片命中——"回得客气点""再压缩一下"

2. **关键词劫持**：`bug`→`code`（"这个 bug 的影响范围"其实是 analyze）、`脚本`→`code`（"演示脚本"

评测暴露的最直接提升点是"可直接采用率"：Standard 档在 `holdout2` 上是 80.0%，剩下 20% 里的
`questions` 此前**只问不收**。本轮补齐了闭环的另一半（`test/` 全绿 **57/57**）：

```bash
node src/cli.js --json --ask --answers '{"deliverable_format":"表格"}'
node src/cli.js --json --ask --answers-file answers.json "帮我写点东西"
```

- 语义：回答写回槽位为 `{ value, confidence: 1, evidence: 回答原文, source: 'explicit', via: 'user.answer' }`
  → 缺口分归零 → 该槽位既不再进 `assumptions` 也不再进 `questions`；列表型槽位走 `asList()` 归一；
  枚举型必须命中本体枚举或追问选项里的中文标签（`表格`→`table`、`英文`→`en`），否则
  `CLARIFY_ANSWER_INVALID`；未知 key 抛 `CLARIFY_ANSWER_UNKNOWN`（message 里列出未知 key 与可用 key）；
  `answers` 为空 / `{}` 时**完全不触碰 IR**（`meta.clarify === null`，老路径逐字节不变）。
- 留痕：`meta.clarify = { rounds: [{ round, asked[], answered{}, skipped[], unknown[], applied[], remaining[] }], appliedAnswers: { slot: { key, answer, value, source, previous } } }`；
  `--json` 新增 `clarify` 字段。
- 已知限制：`deep` 档仍未实现（进入澄清层前显式报错）；未知 key 是**抛错**语义，所以成功路径
  `rounds[0].unknown` 恒为 `[]`；`--ask` 的用法提示行走 **stderr**（stdout 保持可管道）。
